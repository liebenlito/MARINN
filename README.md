# MARINN — Supplementary Materials

Data files, Python source, model checkpoints, and figures accompanying **Maximal-Regularity-Informed Neural Networks: Residual-Based Error Control for Parabolic Problems**.

## Folder organization

Folders `01`–`14` follow the numerical experiments and supporting controls in the manuscript. Experimental measurements are in each folder’s `data/` subfolder. Experiment-specific scripts, where supplied, are in its `code/` subfolder. Shared numerical routines are in the top-level `code/` directory.

`figures/` contains the manuscript figures. `checkpoints/heat_1d/` contains the five-seed trained model weights and associated run histories. `requirements.txt` lists Python dependencies.

Original filenames, CSV values, and source code are retained. Each script can be read alongside the data files for its experiment. The `file_list.csv` file gives the SHA-256 digest and size of each included file.

## Codes and Reproducibility

This directory contains the implementation of the MARINN experiments for one- and two-dimensional partial differential equations. The scripts compare mixed-norm residual training with mean-squared residual training and related controls, including direct nonlinear optimization and Picard iteration.

The experiments cover the heat equation, Burgers equation, a moving-layer test, and the two-dimensional Allen–Cahn equation. Training points and reference solutions are generated by the code; no external dataset is required.

### Files

| File | Purpose |
| --- | --- |
| `marinn_core.py` | Shared models, residuals, training routines, evaluation metrics, and configuration for the 1D experiments. |
| `run_experiments.py` | Main runner for the 1D experiment suite. |
| `run_fair2x2_burgers.py` | Burgers comparison across two loss functions and two nonlinear solution strategies, with equal Adam update counts. |
| `marinn_2d_production_v2_fixed.py` | 2D heat and Allen–Cahn experiments, including a fixed ten-stage Picard comparison. |
| `marinn_2d_heat_credibility.py` | 2D heat studies across seeds, collocation resolutions, and evaluation grids. |
| `validate_allen_cahn_reference.py` | Temporal and spatial refinement checks for the Allen–Cahn numerical reference. |

### Environment setup

Use a separate Python environment. Python 3.10 or later is a reasonable starting point; this directory does not include a pinned dependency file or a recorded reference environment.

Run the following commands from this `code` directory.

**Windows PowerShell**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy pandas scipy matplotlib torch
```

**Linux or macOS**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy pandas scipy matplotlib torch
```

The supplied scripts run on the CPU. A GPU is not required, and the runners do not expose a GPU selection option. For reproducibility, record the Python and package versions used for each study:

```bash
python --version
python -m pip freeze > environment-used.txt
```

### Quick start

Begin with a reduced heat-equation run to check that the environment is working:

```bash
python run_experiments.py --experiment heat_loss --quick --output outputs/heat_quick
```

This command writes `config.json`, `heat_loss_topology_raw.csv`, and `heat_loss_topology_histories.csv` to `outputs/heat_quick`.

To exercise all experiments in the main 1D runner with reduced settings:

```bash
python run_experiments.py --experiment all --quick --output outputs/smoke_test
```

Quick mode uses 100 training epochs, a 20 × 25 training grid, a 12 × 15 validation grid, an 80 × 80 dense evaluation grid, and at most three Picard stages. Unless seeds are supplied explicitly, it uses seed `2024`. These settings are intended for execution checks; they should not be used as substitutes for full experiment results.

### One-dimensional experiments

Run the complete 1D suite with the default settings:

```bash
python run_experiments.py --experiment all --output outputs/full_1d
```

The default seeds are `2024`, `2025`, `2026`, `2027`, and `2028`. The shared configuration uses a network with three hidden layers of width 32, a learning rate of `0.002`, 1,200 epochs per standard training call, and five PyTorch CPU threads. Individual studies adjust budgets or parameters within their own routines.

To run a single study with selected seeds:

```bash
python run_experiments.py --experiment burgers --seeds 2024 2025 2026 --output outputs/burgers
```

| `--experiment` | Study | Main result file |
| --- | --- | --- |
| `heat_loss` | Heat-equation loss comparison | `heat_loss_topology_raw.csv` |
| `q_sensitivity` | Sensitivity to spatial norm exponent, using q = 2, 4, and 8 | `q_sensitivity_raw.csv` |
| `fair_budget` | Heat-equation training-budget comparison | `fair_budget_raw.csv` |
| `quadrature` | Heat-equation quadrature and precision study | `heat_quadrature_precision.csv` |
| `burgers` | Smooth Burgers equation with warm-start, Picard, and optimization controls | `smooth_burgers_all_controls.csv` |
| `wallclock` | Burgers comparison under time budgets | `strict_wallclock_reproduced.csv` |
| `viscosity` | Burgers viscosity study | `viscosity_reproduced.csv` |
| `moving_layer` | Moving-layer test | `moving_layer_reproduced.csv` |
| `all` | All studies listed above, in sequence | All applicable files above |

The Burgers study also writes `picard_stopping_trace.csv` and, when histories are available, `picard_inner_histories.csv`. The quadrature study uses only the first selected seed.

Available command-line arguments are:

| Argument | Default | Description |
| --- | --- | --- |
| `--experiment` | `all` | Select a study from the table above. |
| `--output` | `outputs` | Set the output directory. |
| `--quick` | Disabled | Use the reduced configuration. |
| `--seeds` | Five default seeds, or one in quick mode | Supply one or more integer seeds. |
| `--save-checkpoints` | Disabled | Parsed by the current runner, but not used to save checkpoints. |

Use `python run_experiments.py --help` to inspect the command-line interface. To change settings without a command-line option, edit `Config` in `marinn_core.py` and review any overrides in the selected study.

### Equal-update Burgers comparison

`run_fair2x2_burgers.py` compares `Direct-MSE`, `Direct-MARINN`, `PINN-Picard`, and `MARINN-Picard`. All methods start from a common refined heat checkpoint. Each method receives `K × inner_epochs` nonlinear Adam updates. Heat pretraining and a warm-up step are excluded from the reported nonlinear timings.

Before running locally, update these paths in the script:

- Remove the legacy `sys.path.insert(...)` line that refers to `/mnt/data/marinn_repro_extract/.../code`. The local `marinn_core.py` is available when running from this directory.
- Replace the `OUT` definition and its directory creation with:

```python
OUT = Path("outputs/fair2x2_burgers")
OUT.mkdir(parents=True, exist_ok=True)
```

Run one seed with the default three repeats, three Picard stages, and 400 epochs per stage:

```bash
python run_fair2x2_burgers.py --seed 2024 --repeats 3 --K 3 --inner-epochs 400
```

Repeat the command for each seed required by your study. For a short execution check, use `--repeats 1 --K 1 --inner-epochs 25`.

The script writes `fair2x2_seed2024.csv` and `fair2x2_picard_trace_seed2024.csv` for the example above. The seed is required; the remaining arguments have the defaults shown in the command. Evaluation uses an 80 × 80 grid in float64.

### Two-dimensional production experiments

`marinn_2d_production_v2_fixed.py` runs both the 2D heat and Allen–Cahn studies. Configure its output directory through environment variables to avoid the default `/mnt/data/...` location.

**Windows PowerShell**

```powershell
$env:MARINN_SEED = "2026"
$env:MARINN_THREADS = "1"
$env:MARINN_OUT = "outputs/production_2d/seed2026"
python marinn_2d_production_v2_fixed.py
```

**Linux or macOS**

```bash
MARINN_SEED=2026 MARINN_THREADS=1 MARINN_OUT=outputs/production_2d/seed2026 python marinn_2d_production_v2_fixed.py
```

The default seed is `2026`, and the default thread count is one. The network has three hidden layers of width 48. The heat models train for 500 epochs. Direct Allen–Cahn models train for 500 epochs, while Picard models use ten stages of 250 epochs each. These production comparisons therefore use different update budgets for direct and Picard methods. Picard diagnostics are recorded, but do not stop the fixed ten-stage iteration.

The Allen–Cahn reference uses a 40 × 40 interior spatial grid and Strang splitting with `dt = 0.001`, viscosity `0.01`, and final time `0.4`.

Outputs include:

- `production_summary.csv` and `config.json`.
- Per-method training histories and `.pt` model state dictionaries.
- Allen–Cahn Picard traces.
- `heat_2d_composite.png` and `allen_cahn_2d_composite.png`.

Use a separate output directory for each seed. This script has no command-line parser or quick mode; training settings are defined near the top of the file.

### Two-dimensional heat credibility studies

Before running `marinn_2d_heat_credibility.py`, replace its hard-coded `OUT` definition and directory creation with:

```python
OUT = Path("outputs/heat_2d_credibility")
OUT.mkdir(parents=True, exist_ok=True)
```

Then run:

```bash
python marinn_2d_heat_credibility.py
```

The script runs the following studies in sequence:

1. A five-seed comparison of `PINN-MSE`, `Flat-L4-squared`, and `MARINN`, using seeds `2024`–`2028`.
2. Collocation sensitivity at 10 × 10 × 12, 14 × 14 × 16, and 18 × 18 × 20 points, using seeds `2024`, `2026`, and `2028`.
3. Evaluation-grid convergence at 36 × 36 × 21, 64 × 64 × 41, and 96 × 96 × 61 points, using the saved seed-`2026` models.

The default training budget is 500 epochs per model. `MARINN_THREADS` controls the PyTorch thread count, with a default of two. There are no command-line options for selecting individual studies. If calling `run_evalgrid()` separately, first generate the checkpoints through `run_main5()`.

Results are saved as `heat2d_conditioned_main5_raw.csv`, `heat2d_conditioned_main5_summary.csv`, `heat2d_collocation_sensitivity_raw.csv`, `heat2d_collocation_sensitivity_summary.csv`, and `heat2d_evaluation_grid_convergence.csv`. Per-seed folders contain histories and model state dictionaries; the completed run also writes `config.json`.

### Allen–Cahn reference validation

Run the reference refinement checks independently of neural network training:

```bash
python validate_allen_cahn_reference.py
```

The script compares time steps `0.002`, `0.001`, and `0.0005` on a 40 × 40 interior grid, then compares 40 × 40 and 81 × 81 spatial grids at `dt = 0.0005`. The finer solution is restricted to the matching coarse nodes.

Results are written to `reference_validation/allen_cahn_reference_convergence.csv` and `reference_validation/production_reference_vs_refined.csv`. Both files report relative L2 and maximum absolute differences. This script runs its calculations on import, so execute it directly rather than importing it solely to inspect its functions.

### Interpreting and preserving results

The 1D result tables include `rel_L2_exact` for relative solution error, `residual_L2tL4` for the mixed residual norm, derivative error norms, `E_MR`, and `max_residual`. In the shared 1D evaluator, `E_MR` is the time-derivative error norm plus the viscosity-weighted second spatial derivative error norm. The 2D scripts use their own evaluation routines and column names; interpret each table using the corresponding implementation.

Keep quick runs and full runs in separate directories. Reusing an output directory can overwrite files with the same names. The main 1D runner saves the shared configuration, but selected seeds and all study-specific overrides are not included in that file. Preserve the command, any source edits, package versions, and hardware details alongside the outputs.

Fixed seeds support repeatable sampling and initialization. Numerical results and wall-clock measurements can still vary across package versions, processors, thread counts, and system load. Full runs involve repeated training and dense derivative evaluations, so their duration depends on the selected studies and available CPU resources.

### GPU Execution Guide for MARINN
PyTorch models and computational grids automatically use CUDA when it is
available. Otherwise, execution falls back to the CPU. GPU execution requires
a CUDA-enabled installation of PyTorch and a compatible NVIDIA driver.

To run a short validation experiment, execute:

```powershell
python run_experiments.py --experiment heat_loss --quick --device cuda
```

To run all experiments on the GPU, execute:

```powershell
python run_experiments.py --device cuda
```

Explicit GPU selection is also supported by `run_fair2x2_burgers.py`:

```powershell
python run_fair2x2_burgers.py --seed 2026 --device cuda:0
```

For the two-dimensional scripts or programmatic use through Python imports,
set the environment variable before starting Python:

```powershell
$env:MARINN_DEVICE = "cuda:0"
python marinn_2d_production_v2_fixed.py
python marinn_2d_heat_credibility.py
```

Use `cpu` to require CPU execution or `auto` to enable automatic device selection.
An explicit request for CUDA raises an error if CUDA is unavailable.

Randomized grids are generated using a CPU random number generator and then
transferred to the model's device. This preserves consistent collocation samples
across devices. NumPy conversions and the NumPy/SciPy reference solvers continue
to execute on the CPU. In particular, `validate_allen_cahn_reference.py` remains
a CPU-based NumPy/SciPy reference solver.

Training scripts write results to `outputs/` by default. For the two-dimensional
scripts, the output directory can be configured through the `MARINN_OUT`
environment variable.

### Troubleshooting

- **Missing Python packages:** Activate the environment and install dependencies with `python -m pip install numpy pandas scipy matplotlib torch`.
- **Errors involving `/mnt/data`:** Apply the local output-path changes described above. Only the 2D production script reads `MARINN_OUT`; the fairness and heat credibility scripts require source edits.
- **Unable to import `marinn_core`:** Keep the supplied scripts together and run commands from this directory.
- **Long runs or high memory use:** Start with a single quick study and one seed. The standalone 2D scripts do not provide a quick flag; reduce their source-level settings only for execution checks and record those changes.
- **Plotting issues on a headless machine:** Set `MPLBACKEND=Agg` before running scripts that import Matplotlib. In PowerShell, use `$env:MPLBACKEND = "Agg"`; in Bash, use `export MPLBACKEND=Agg`.
